## v0.4.0 追加：J/L 音画错位（同日）

- cut 接点支持 `jcut`/`lcut`（秒）：jcut 让入镜音频提前进入，lcut 让出镜音频在画面切走后继续。音频独立放置，以采样级 `adelay` + `amix` 合成；视频仍走 concat/xfade。扩展音频在边界处与各自画面保持同一源时间，因此切点后仍同步。
- 全量测试：**166项通过**（新增6项：J/L 音频范围与越界校验、音频错位不影响字幕归属、真实 440/880Hz J-cut 与 L-cut、引擎计划/预览及越界拒绝）。
- 真实证据：J-cut 0.5s 的合成片中，画面切点前 1.6–1.9s 已测得 880Hz，切点后仍为 880Hz；L-cut 0.5s 在切点后 2.1–2.4s 仍测得 440Hz，随后进入 880Hz。视频帧数、音视频时长与完整解码QC通过。
- 真实CLI：`init → plan → preview → approve → render` 使用 jcut 0.5s 全流程退出码0，计划记录 jcut_frames=12，成片4.0秒；解码后在 1.6–1.9s 测得 880Hz、切点后仍为 880Hz。报告见 [.video-agent/jl-demo-20261103/report.json](../.video-agent/jl-demo-20261103/report.json)。
- 局限：只在 cut 接点生效；扩展不得超出源片范围；重叠音频直接求和，没有自动 ducking、限幅或电平自动化；仍未实现多机位、节拍检测或自动对白优先。

## v0.3.0 追加：逐接点转场（同日）

- 同一交付形态新增 `transitions`：每个接点可独立选择 cut 或非cut转场；plan 中 `transition` 与 `transitions` 互斥，旧计划继续按统一 `transition` 解释。
- 全量测试：**160项通过**（新增11项：逐接点时间轴与校验、逐接点字幕归属、真实 cut+fade 混排渲染（含反向/交替顺序、无声源、分数帧率）、硬切颜色边界、审阅、引擎计划/预览/渲染、互斥校验）。
- 真实渲染：3色6秒合成素材，接点1 `fade 0.4s`、接点2 `cut`；成片5.6秒，帧数与完整解码QC通过；接点2前后解码像素分别为绿、蓝，证明硬切没有用极小xfade冒充。
- 字幕在fade接点按交叠中点归属，在cut接点直接交界，无重叠。
- v0.3.0 时仍未实现独立J/L-cut；v0.4.0 已补齐 cut 接点的 J/L（见上节）。仍没有逐接点不同音频处理、节拍检测/踩点、多机位。

## 独立审查与修复

1. 音频和授权记录原为平级artifact，缓存未递归校验授权文件：现计划显式绑定music_license，记录rights_confirmed和音乐sha256，根计划依赖包含授权文件。篡改/删除授权记录后计划缓存、预览和渲染拒绝继续。
2. 缺授权绑定的旧音乐计划：fail closed，必须重新生成并审批，不原地补写已注册计划。原始无音乐计划保留兼容。
3. 原始旧计划按逐段毫秒累加会在24/29.97fps多段剪辑中累计误差：现渲染统一重建实际帧时间轴，并校验与已审批片长一致；不一致要求新计划。500段正/负累积偏移回归通过，字幕尾与实际时长差不超过1ms。

## 证据与局限

- 所有验证素材自行生成；音乐权利确认只是用户声明记录，不构成法律意见。
- 镜头建议基于时长、黑场与静帧比例，不是语义高光/人物/情绪评分。Harness模型应在实际查看图像和转写后修订。
- 审阅会提示短/长镜头、重复源区间、词/句内切点、原音转场交叠、黑边遮盖风险；不保证故事、表演、连续性或主观审美正确。
- v0.2.0 当时为统一转场；v0.3.0 已支持逐接点 cut/fade 混排，v0.4.0 已支持 cut 接点的 J/L 音画错位；但仍没有逐接点复杂音频处理、节拍检测/踩点、多机位动作匹配、主体跟踪、口型同步、专业色彩匹配或复杂特效。
- 配乐压低基于音频能量而非语音识别；音乐或噪声也会触发。
- ASR模型权重仍未下载；Argos/Piper仍未安装；本机默认FFmpeg仍缺libass，硬字幕依旧未真实验证。升级没有悄悄安装这些依赖。
- 最终水平需要用户提供真实素材、明确风格与目标后做审美验收；149项测试与合成示例不能证明“电影级自动剪辑”。
